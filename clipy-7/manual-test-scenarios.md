# Clipy Studio Manual Smoke-Test Matrix

Run these checks on a small emulator and at least one physical Android device when possible. Automated JVM tests cover repository, timeline, render, export, and share-state regressions; these manual checks cover Android picker, permission, playback, storage, and share-sheet behavior that local unit tests cannot fully validate.

| ID | Scenario | Preconditions | Steps | Expected result | Manual-only notes |
| --- | --- | --- | --- | --- | --- |
| M01 | Image-only project | Fresh app install with one local image available | Create a project, import one image, open the editor timeline | One image clip appears, timeline duration is non-zero, playback-only controls are disabled when no playable audio/video exists, edit/export controls remain available | Verify compact layout on a narrow device and readable helper text |
| M02 | Video-only project | One short local MP4 available | Create a project, import one video, select it, seek, trim right edge, split near the middle | Video duration maps from metadata, trim and split update timeline and preview without desync | Confirm touch targets are at least 48 dp where practical |
| M03 | Mixed image/video project | One image and one video available | Import both assets with multi-select, reorder clips, seek across the boundary | Clip order and total duration remain consistent, selected clip state is visible | Verify timeline labels do not overlap on small screens |
| M04 | Add music | One audio file available | Use the audio/music action and pick a file | Audio lane gets a real clip, or unavailable/permission state is shown without fake success | Requires Android picker access |
| M05 | Extract audio | A video clip is selected | Use extract audio if enabled | Extracted audio appears only for compatible video selections; image-only selection shows unavailable state | If disabled, confirm disabled label explains why |
| M06 | Add text | Active project with at least one visual clip | Add text, edit content/style, move selection, undo and redo | Text overlay is selected, editable, restored by redo, and visible after reopening the project | Verify text remains readable in dark UI |
| M07 | Add sticker | Active project with at least one visual clip | Add a bundled sticker, move it, duplicate/delete if controls exist, undo/redo | Sticker uses a real bundled/local asset path or clearly unavailable state; no placeholder success | Check accessibility label includes selected state |
| M08 | Apply filter/effect | Compatible clip selected | Apply filter and effect controls | Compatible clip/effect lane mutates visibly; unsupported or missing selection stays disabled with feedback | Verify color is not the only selected indicator |
| M09 | Transition | Two adjacent visual clips exist | Move playhead near a clip boundary and apply fade/slide/zoom/blur transition | Transition is added only at a valid boundary and can be removed/undone | Boundary affordance should be visible enough to test |
| M10 | Trim, split, reorder | Project has at least two visual clips | Trim, split, drag/reorder, then undo/redo each operation | Timeline, playhead, preview, clip IDs, and durations remain synchronized | Watch for jumpy scrolling or snap errors |
| M11 | Reopen draft | Project has imports, text/sticker/effect, and changed export settings | Close app/process if possible, reopen project | Draft restores latest clips, overlays, export settings, and safe selection state | Requires process restart or recents dismissal |
| M12 | Export 720p | Exportable project open | Select 720p MP4, start export | Progress, cancel, success, and output readiness states are shown; exported file plays | Validate actual playback outside the app if possible |
| M13 | Export 1080p | Exportable project open | Select 1080p MP4, start export | Same supported MP4 path completes or reports recoverable device limitation | Use mid-range device when available |
| M14 | Cancel export | Export is running | Tap Cancel | Progress stops, state returns to editor/export panel, no new share URI is fabricated | Share remains disabled unless an earlier real export exists |
| M15 | Share video | Export completed successfully | Tap Share | Android share sheet opens with exported MP4 URI and video MIME type | Requires device/emulator share targets |
| M16 | Permission denied | App has no media permission or picker permission is denied | Attempt media import and deny permission | Visible error/recovery message appears, no clip is added, prior timeline remains intact | Use system settings to reset permission |
| M17 | Missing file | Import a file, remove/revoke it externally, reopen project/export | Affected clip is marked missing or import fails visibly; project is not destructively cleaned | Use removable/document-provider media when possible |
| M18 | Low storage export | Device/emulator storage is constrained or storage failure is simulated | Start export | Export fails with storage/free-space recovery message, no output URI exists, Share stays disabled | Prefer emulator storage pressure simulation |

UI verification checklist: spacing remains consistent in portrait and landscape, typography hierarchy matches existing Material 3 styling, disabled states include text/semantics not only color, export/error messages are readable, and bottom controls remain reachable on small screens.
